# 항공자동조회 개념정리

작성일: 2026-06-29

## 한줄 결론

항공자동조회는 기존 ERP 요금 업로드와 분리된 별도 프로젝트이며, 노선/편명 마스터를 기준으로 TOPAS 출발편과 귀국편을 자동 조회하고, 날짜별 운항 여부와 가용 클래스를 모아 요금계산과 엑셀 생성까지 이어가는 구조다.

## 프로젝트 범위

이 프로젝트는 기존 `ERP 행사요금일괄수정 + 구글시트 최저가 업데이트` 프로젝트와 별개다.

포함 범위:

- 노선/편명 마스터 관리
- 조회 시작일/조회 종료일 기준 항공편 조회
- TOPAS 출발편 조회 명령 생성
- TOPAS 귀국편 조회 명령 생성
- TOPAS 순차 입력 및 AC1 반복
- TOPAS 원문 저장
- 날짜별 운항 여부와 가용 클래스 요약
- 귀국편 시간 기준 박수 자동 계산
- 요금계산
- 엑셀 생성

제외 범위:

- ERP 행사요금일괄수정 화면 직접 저장
- 구글시트 F/G열 업데이트
- ERP 진행구분/정보일괄수정 변경
- 기존 ERP 요금 업로드 프로젝트와의 자동 연결

기존 ERPUpdater에는 TOPAS 자동조회와 요금계산에 활용할 수 있는 모듈이 이미 있다.

| 모듈 | 역할 |
|---|---|
| `topas.availability` | TOPAS AN/AC1 조회 명령 생성, availability 응답 파싱 |
| `topas.pacing` | TOPAS 응답 완료 대기와 다음 명령 전송 타이밍 판단 |
| `topas.collector` | TOPAS 원문 블록 저장 |
| `fare.parser` | TOPAS 원문에서 날짜별 가용 클래스 추출 |
| `fare.store` | Firestore 또는 `cache/fares_snapshot.json` 운임/시즌 데이터 로드 |
| `fare.calculator` | 출발편/귀국편 원문과 박수 기준 왕복요금 계산 |
| `fare.exporter` | TSV, Excel, ERP 입력표 형태로 변환 |

주의할 점:

- 기존 요금계산은 TOPAS `FXP/FQQ` 실시간 운임 계산이 아니다.
- 기존 방식은 TOPAS AN/AC1 좌석조회 원문과 별도 운임 DB를 조합해 계산한다.
- 따라서 항공자동조회 MVP에서는 먼저 availability 조회와 원문 저장을 안정화하고, 요금계산은 그 다음 단계로 붙이는 것이 좋다.

## 노선/편명 마스터 개념

사용자가 준 원본 형식:

```text
ICNDAD_LJ081/2
ICNDAD_7C2217/8
ICNDAD_ZE593/4
```

해석 규칙:

- 앞 6글자: 왕복 노선
- 앞 3글자: 출발지
- 뒤 3글자: 목적지
- 언더바 뒤: 항공사 + 출발편명
- 슬래시 뒤 숫자: 귀국편 끝번호

예시:

```text

```

해석:

| 출발 노선 | ICN-DAD |
| 귀국 노선 | DAD-ICN |
| 항공사 | ZE |
| 출발편 | ZE593 |
| 귀국편 | ZE594 |

## 상품일수와 박수

현재 주로 다루는 상품은 5일짜리 상품이다.

5일 상품은 귀국편 출발 시간이 자정 이전인지 이후인지에 따라 박수가 갈린다.

| 상품일수 | 귀국편 출발시간 | 박수 | 귀국편 조회일 |
|---:|---|---:|---|
| 5일 | 24시 이전 | 3박 | 출발일 + 3일 |
| 5일 | 00시 이후 | 4박 | 출발일 + 4일 |

주의할 점:

- 귀국편 출발시간은 항공사/노선/편명마다 하나로 고정된 값이라고 보면 안 된다.
- 같은 항공사, 같은 노선, 같은 귀국편이라도 시즌에 따라 A시즌은 23시대, B시즌은 01시대 출발일 수 있다.
- 따라서 박수 계산은 `flight-master.mjs`의 고정 귀국시간이 아니라, 날짜별 TOPAS 귀국편 조회 결과에서 파싱한 실제 출발시간을 기준으로 확정해야 한다.

미래에 6일 상품을 만들 수 있으므로, 상품일수와 박수는 분리해서 설계해야 한다.

일반 규칙:

```text
귀국편이 24시 이전 출발 = 상품일수 - 2박
귀국편이 00시 이후 출발 = 상품일수 - 1박
```

예시:

| 상품일수 | 귀국편 출발시간 | 박수 | 귀국편 조회일 |
|---:|---|---:|---|
| 5일 | 23:30 | 3박 | 출발일 + 3일 |
| 5일 | 00:30 | 4박 | 출발일 + 4일 |
| 6일 | 23:30 | 4박 | 출발일 + 4일 |
| 6일 | 00:30 | 5박 | 출발일 + 5일 |

## TOPAS 조회 명령 개념

출발편 조회:

```text
AN{날짜}{출발지}{목적지}/A{항공사}{출발편번호}
```

귀국편 조회:

```text
AN{날짜}{목적지}{출발지}/A{항공사}{귀국편번호}
```

예시:

```text
마스터: ICNDAD_ZE593/4
출발일: 2026-07-01
상품일수: 5일
박수: 3박
```

생성 명령:

```text
출발편: AN01JULICNDAD/AZE593
귀국편: AN04JULDADICN/AZE594
```

4박으로 계산되는 귀국편이면:

```text
귀국편: AN05JULDADICN/AZE594
```

## 조회 순서 개념

권장 순서:

1. 노선/편명 마스터를 읽는다.
2. `flight-master.mjs`의 노선 값을 기준으로 노선 카테고리를 선택한다.
3. 조회 시작일과 조회 종료일 기준 날짜 목록을 만든다.
4. 상품일수 기본값을 적용한다. MVP 기본값은 5일이다.
5. 출발편 TOPAS 조회 명령을 생성한다.
6. TOPAS에 출발편 명령을 순차 입력하고 AC1 반복으로 원문을 모은다.
7. 출발편 원문을 저장한다.
8. 상품일수 기준 귀국편 후보일을 만든다.
   - 5일 상품이면 3박 후보일과 4박 후보일을 모두 만든다.
   - 6일 상품이면 4박 후보일과 5박 후보일을 모두 만든다.
9. 귀국편 후보일별 TOPAS 조회 명령을 생성한다.
10. TOPAS에 귀국편 후보 명령을 순차 입력하고 AC1 반복으로 원문을 모은다.
11. 귀국편 원문에서 실제 귀국편 출발시간을 파싱한다.
12. 파싱한 시간 기준으로 날짜별 박수를 확정한다.
13. 날짜별 운항 여부와 가용 클래스를 요약한다.
14. 요금계산을 수행한다.
15. 엑셀을 생성한다.

## 저장해야 할 핵심 데이터

노선/편명 마스터에는 최소한 아래 항목이 필요하다.

| 필드 | 설명 |
|---|---|
| `key` | 원본 식별자 |
| `origin` | 출발지 |
| `destination` | 목적지 |
| `route` | 표준 노선명 |
| `airline` | 항공사 코드 |
| `depFlight` | 출발편명 |
| `retFlight` | 귀국편명 |
| `retDepartureTime` | 선택 입력값. 기본은 날짜별 TOPAS 결과에서 감지하며, 이 값은 임시 보정/수동 확인용으로만 사용한다. |
| `defaultProductDays` | 기본 상품일수 |
| `enabled` | 자동조회 사용 여부 |

## 남은 핵심 확인사항

- 귀국편 후보일 조회 결과에서 실제 출발시간을 안정적으로 파싱해야 한다.
- 같은 편명의 귀국시간이 시즌별로 23시대/01시대로 바뀌는 경우를 날짜별로 감지해야 한다.
- `NO FLIGHT` 응답을 비운항으로 볼지, 재조회 대상으로 둘지 정책이 필요하다.
- 360일 조회를 한 번에 실행할 때 TOPAS 응답 속도와 세션 안정성을 확인해야 한다.
- 요금계산은 기존 운임 DB 방식으로 할지, 나중에 TOPAS `FXP/FQQ` 실시간 운임 방식까지 확장할지 결정해야 한다.
